# 新平食品（宁波洪晟）· 调味品供应链协同系统

给一家复合调味酱工厂做的产销协同系统：业务员打卡、门店订货、工厂排产、司机配送、老板看板。
后端是纯 Python 标准库 + SQLite，前端是三个独立页面 + 一个微信小程序。

---

## 30 秒跑起来

```bash
pip install openpyxl==3.1.5
python 07_p1_server.py
```

打开 <http://127.0.0.1:8765/>，用 `boss` / `demo1234` 登录。

## 它解决什么

工厂做复合调味酱（74 个 SKU、1kg 袋装为主、也能 10g–1000g 小袋分装），客户是连锁餐饮。
痛点是：接单靠微信、库存靠 Excel、业务员在外面看不见、定制配方版本乱、换口味要洗锅。

所以这套东西的主线是：

```
扫街 → 建档 → 打卡 → 试菜 → 首单 → 订单 → 排产 → 入库 → 拣货 → 配送 → 签收 → 应收 → 回款
```

每个环节都能跑通，权限按角色隔离（业务员看不到别人的门店，也看不到成本）。

## 三个做过的判断

**1. 主数据留空不等于系统不能用。**
字段不写"必填/可空"，而是"对哪个动作必填"：缺箱规→不能按箱下单，但不影响建档、入库、发货。
拦截信息会直接指到表格第几列，填表的人不用问开发。

**2. 排产的价值在"少洗几次锅"，不是算法多聪明。**
"按交期排好再塞给最早空闲的锅"会让两台锅互相插花，洗锅次数跟工单数一样多。
改成"按品类族成块、整块分给锅"，12 张工单从 10 次洗锅降到 4 次，省 215 分钟。

**3. 权限必须在 SQL 层。**
行级过滤是查询条件的一部分，成本字段服务端直接不回传。前端藏起来的东西，打开开发者工具就看见了。

## 已知边界

- 没有 BOM / 配方 / 质检 / 采购 / 成本核算，排产不校验原料
- 没有多仓、多租户
- 没有改密码界面
- SQLite 单写锁，几十人够用，再大要换 PostgreSQL
- 小程序没有在真机上验证过（本机没有开发者工具和 AppID）
